カレンダー

自分のメインカレンダーは primary を指定します。

カレンダーIDの取得方法

自分のメインカレンダーだけを使う場合は、primary のままでOKです。

  1. PC版のGoogleカレンダーを開き、左側の対象カレンダーにマウスを合わせます。
  2. 「︙ → 設定と共有」を開きます。右上の歯車 →「設定」から対象カレンダーを選んでも構いません。
  3. 「カレンダーの統合」にある「カレンダーID」をコピーして、この欄へ貼り付けます。

カレンダーの表示名、公開URL、埋め込みコードではありません。共有カレンダーの場合も同じ手順です。今ログインしている会社アカウントに、そのカレンダーの予定を確認できる閲覧権限が必要です。

件名の先頭と文字どおりに照合します。空白もそのまま保存します。

LINE 送信先

Messaging API User IDの取得方法
  1. LINE Developersコンソールを開き、対象のプロバイダー → この通知に使うMessaging APIチャネルを選びます。
  2. 「チャネル基本設定」タブを開き、下の方の「あなたのユーザーID」をコピーします。
  3. Uで始まる33文字の値を、この入力欄へ貼り付けます。送信先の種類は「ユーザー」を選び、通知用のLINE公式アカウントを友だち追加してください。

プロバイダーID・チャネルID・友だち検索用のLINE IDではありません。「あなたのユーザーID」がない場合は、ビジネスIDとLINEアカウントの連携を確認してください。

対象チャネルが見つからない場合は、LINE Official Account Managerの「設定 → Messaging API → Messaging APIを利用する」を先に完了してください。

  1. LINE Developersで、通知に使うMessaging APIチャネル →「Messaging API設定」を開き、「グループトーク・複数人トークへの参加を許可する」を有効にします。
  2. LINEアプリで、通知用のLINE公式アカウントを対象グループへ招待します。同じグループに複数のLINE公式アカウントは参加できません。
  3. グループIDの取得には、管理者が用意した信頼できるWebhook受信先が必要です。同じチャネルの「Webhook設定」で受信先URLを設定し、「Webhookの利用」を有効にします。既存の受信先がある場合は、別の連携を止めないよう管理者へ確認してください。
  4. 対象グループでメッセージを送り、受信先でLINEの署名を検証したイベントのsource.groupIdを確認します。source.userIdではありません。Cで始まる33文字の値がグループIDです。
  5. この画面の種類を「グループ」にし、取得したIDを「Messaging API Group ID」欄へ入力します。同じ公式アカウントのチャネルアクセストークンも必要です。グループ名・招待URL・個人のUser IDでは送信できません。
  6. 「LINE設定を保存」後、「テスト送信」で対象グループへの到着を確認します。メッセージはグループの全メンバーに表示され、通知枠を消費します。

このアプリにはWebhook受信機能はありません。受信先が未用意の場合は、先に管理者による受信先の準備・グループIDの取得が必要です。個人宛ての設定のまま招待しても、通知先はグループへ切り替わりません。

チャネルアクセストークンの取得方法
  1. LINE Developersコンソールで、通知を送信するLINE公式アカウントのMessaging APIチャネルを開きます。ユーザー宛て・グループ宛てのどちらでもトークンは必要です。
  2. 「Messaging API設定」タブを開き、下の方の「チャネルアクセストークン（長期）」で「発行」を押します。
  3. 発行された値をコピーして、このパスワード欄へ貼り付け、「LINE設定を保存」を押します。

チャネルIDやチャネルシークレットではありません。トークンはチャットや共有文書へ貼らず、この入力欄に直接登録してください。再発行すると、同じ古いトークンを使う別の連携にも影響するため注意してください。

空欄で保存するとトークンを削除します。

監視の操作

カレンダー設定の保存だけでは稼働中の監視は変わりません。保存後に「監視を開始・更新」で適用します。

開始・再開や監視対象の変更時は初期同期します。同じ設定での更新は監視基準を維持します。テスト送信は実際のLINE通知枠を消費します。
